# Проверка и границы доверия к учебному контенту

Дата среза: **2026-10-04**. Проверка относится к указанным файлам и их SHA, а не к любой последующей редакции или к статусу в работающей базе. **Human approval: 0.** Никакой результат скрипта, модельная рецензия или успешный импорт не заменяет одобрение преподавателя-предметника.

Pilot и core проверял другой агент. Языки и Python получили дополнительный проход от своего автора; это не следует называть независимой предметной экспертизой. Выборка — вопросы 3 и 8 каждой из 45 школьных тем, все десять typed-вопросов pilot и вопросы 2 и 5 шести уроков Python. Итого: pilot 40, core 32, languages 28, Python 12. Это охват по фиксированному правилу, а не статистическая оценка точности всей базы.

В выборке не обнаружено ошибочного ключа или смыслового расхождения RU/KZ. Прочитаны оба shared reading context, проверены все 20 ссылок. Исправлены пробелы между формулами и текстом, внутренние `REF-02` в ученических объяснениях и регистр идентификаторов Python в казахских инструкциях. Идентификаторы и имена файлов Python чувствительны к регистру. ## Автономный CI gate

Из корня репозитория, Python 3.11+ (проверено на 3.12.14), сторонние пакеты и сеть не нужны:

```sh
python content/starter/check_pilot.py
python content/starter/check_core.py
python scripts/validate_content.py
```

Последняя команда — основной самостоятельный CI gate. Она проверяет:

- неизменность трёх пользовательских источников по исходному INPUT_MANIFEST;
- соответствие programme SHA реестру скачиваний, непрерывность и уникальность кодов, допустимые номера страниц, язык/вариант/год;
- полный перечень 18 направлений, отдельные 45 starter-уроков, соответствие каждого урока **своему** предмету и существующему официальному коду;
- 450 уникальных RU prompts, непустые RU/KZ поля, theory ≥1500 символов, отсутствие одинакового theoryRu/theoryKz;
- уникальность option ID и текстов, единственную форму ключа, существование всех ответов, 1–3 ключа multiple, полное покрытие двух левых элементов matching;
- отсутствие скрытой подмены авторских вопросов официальными или human-approved, наличие всех пяти модельных reviewChecks;
- контексты: существование, RU/KZ содержание, отсутствие чужих/потерянных ссылок;
- действующую Конституцию K2600000000, дату 2026-07-01 и статьи в сохранённых официальных отрывках;
- актуальность proof/sample-review SHA и совпадение ключей в отчётах с текущими вопросами;
- quiz, задания и примеры Python, повторное исполнение 12 примеров и восьми границ;
- согласованность экзаменационных сумм, допустимых пар и scoring source; запрет `officialSimulatorReady=true` для этого неполного банка.

Исполнитель кода используется только для проверенных авторских примеров. Он допускает ограниченный учебный синтаксис, запрещает imports и неподдерживаемые вызовы/атрибуты, запускает отдельный процесс с трёхсекундным лимитом и разрешает доступ только к объявленным fixture-файлам во временной папке. Это средство проверки репозиторного материала, **не сервис выполнения произвольных ученических программ**.

По умолчанию байты research-кэша не требуются для CI. Если они локально существуют, их размер и SHA сверяются. Для аудита полного локального скачивания:

```sh
python scripts/validate_content.py --verify-cache
```

Оба режима прошли на зафиксированном срезе: 18 направлений, 748 пунктов, 45/450 starter, 6/30 Python, 112 model sample checks, 0 human approvals, `fullEntBankReady=false`; дополнительно сверены все 77 локальных записей НЦТ и разрешённый Python PDF. Команда не выполняет HTTP и не меняет базу.

Дополнительно проверено 11 намеренных повреждений данных в памяти: несуществующий правильный ID, повтор option, чужой context, связь с чужим предметом, устаревшая дата закона, страница PDF вне диапазона, потерянная отметка неопределённости, ложная готовность официального симулятора, устаревший proof hash, запрещённый import в примере и неверный stdout. Все 11 отвергнуты; исходные JSON не изменялись.

## Фактический браузерный проход опубликованного контента

На локальном Docker-приложении `http://127.0.0.1:8081` выполнено:

```sh
.venv/Scripts/python.exe scripts/content_browser_tests.py
```

Новый ученик зарегистрирован через форму, вышел и снова вошёл через форму. Для каждого из 18 направлений: карточка предмета → готовый урок → чтение и отметка теории прочитанной → десять ответов через controls интерфейса → завершение → результат и объяснения. Правильные ключи взяты из авторских JSON; student API не использовался для получения ключей или отправки ответов. Отдельный admin request context разрешает внешние ключи опубликованных записей и создаёт/архивирует технический rendering fixture; его token не передаётся ученическому браузеру.

Результат: **18 attempts, 180 сохранённых правильных ответов, 18 предметов в реальной статистике**. Пройдены 175 single, 3 multiple и 2 matching вопроса; 10 reading-вопросов показывали общий контекст на KZ. Во всех 180 ответах API с очередным вопросом отсутствуют правильные ключи и объяснения; объяснения доступны на итоговом экране. Browser page/console/network/HTTP errors: 0.

Длинная теория прямоугольного треугольника с формулами в тексте проверена в RU и KZ на ширинах **320, 390, 768, 1024, 1440**. Horizontal overflow: 0; axe WCAG2A/AA и WCAG2.1AA violations: 0. Дополнительно axe проверил регистрацию/вход, multiple, matching, общий текст и итоговую статистику. Это не ручной accessibility-аудит и не проверка всех страниц приложения.

Отдельный временный RU/KZ материал содержит настоящие inline/display LaTeX, Markdown-таблицу из четырёх колонок и CODE block. Проверены созданные `.katex` узлы без `.katex-error`, строки таблицы, текст кода, axe и page overflow на 320/390. Table region получает focus, ArrowRight действительно изменяет его scrollLeft; страница не расширяется. Прочитаны итоговые мобильные screenshots. Выявленные при первом проходе блокировка встроенного шрифта CSP и расширение grid из-за таблицы исправлены: шрифты стали отдельными same-origin assets, контейнеры получили ограничение ширины. Финальный общий запуск **2026-10-04 04:45–04:46 UTC: PASS**, 22 автоматические инспекции. Все три технические записи архивированы и больше не видны в student catalog; они не входят в 45 starter-уроков/450 вопросов.

Для отдельной проверки renderer без повторения 18 тестов: `python scripts/content_browser_tests.py --render-only`. Она пишет отдельный `rendering-report.json`, создаёт нового ученика через UI и всегда пытается архивировать временный subject/topic/theory. Ошибка cleanup делает результат FAIL; исходные учебные материалы не изменяются.

Машинный runtime-отчёт сохраняется в ignored `test-results/expansion/content-browser/report.json`; секреты одноразового ученика — только в ignored fixture-файле. Публикуемые снимки: [docs/screenshots/expansion/content](screenshots/expansion/content). Скрипт не делает API-bypass ученических ответов и не скрывает ошибки сети. Каждый новый запуск создаёт нового локального ученика и новые реальные attempts.

## Что проверка не обещает

Структурная валидность не доказывает педагогическую достаточность, отсутствие всех фактологических/переводческих ошибок, баланс сложности или психометрическую калибровку. Уровни easy/medium — авторские метки, не статистически установленная сложность официального ЕНТ. Повторяющиеся позиции правильных ответов ограничивают пригодность этого небольшого банка для экзаменационной оценки.

Флаги `sourceRead`, `extractionChecked`, `answerChecked`, `translationChecked`, `explanationChecked` описывают модельную работу; они не дают `verified=true`. Полный банк ЕНТ, полное покрытие всех языковых вариантов и человеческое одобрение остаются будущей работой. App E2E, authorization, immutable attempt snapshots и безопасные download API проверяются тестами приложения, не этим документом.

## Изменение и повторная проверка

Менять нужно авторский источник, затем regenerate соответствующего файла и rerun proofs. Для pilot/core генераторы сохранены в `content/starter/build_pilot.py` и `build_core.py`; languages/Python — самостоятельные авторские JSON, не генерируемые этими двумя скриптами. После любого изменения файл перестаёт совпадать с hash второго прохода: перечитать затронутые ответы и контекст, затем осмысленно обновить review record. Нельзя просто подставить новый hash, не проверив изменение.

Изменение вопроса после первого release не должно случайно менять его stable external key. Работа с импортом и конфликтом ручной редакции описана в [CONTENT_RELEASE.md](CONTENT_RELEASE.md). Валидатор источников не объявляет успешное применение, публикацию или re-run идемпотентность; для этого нужны отчёты release CLI и проверки базы.
