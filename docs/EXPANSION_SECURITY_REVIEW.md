# Expansion backend security and compatibility review

Review date: 2026-10-04. Scope: the working tree on `codex/education-content-experience`, including assessment/context snapshots, content packs, bulk operations, import authorization/transactions, public/offline publication, request-body limits, and the new personal-study/submission integrations. This was source review with targeted adversarial integration checks, not a production penetration test or a load-test certification.

The identified P1 disclosures are fixed and verified. No unresolved P0/P1 was found in the reviewed backend paths after these changes. The release owner still performs the final whole-repository regression, container rebuild, browser, and accessibility checks; those results must not be inferred from this review's targeted run.

## Authorization and transaction checks

- Content-pack preview, confirmation, mapping, and conflict endpoints require ADMIN or CONTENT_EDITOR through `Actor.editorOnly()`. Batch confirmation rechecks its owner/admin rule, existing content ACLs, expected versions, and a recomputed preview while holding the namespace lock. Writes and audit events share the service transaction. Repeated confirmation of an applied batch returns its saved result; a reused batch key with a different request hash returns 409.
- The original JSON/CSV import remains a draft-creation workflow. Confirmation locks its import record, checks ownership and references again, and delegates creation into the same transaction. Invalid rows do not partially import. Bulk publication is restricted to editors/admins, locks target rows in a stable order, validates a preview token containing actor/content/version/checksum data, and delegates transitions inside one transaction.
- Source-registry URLs are stored and validated as metadata; the service does not fetch them. A null source row now yields a validation error instead of an NPE.
- The material-library endpoint returns metadata only. Its query applies editor access or the current teacher's ownership of non-ENT content to both the page and count. `materialLibraryKeepsTeacherOwnershipAndStudentIsolation` verifies teacher isolation, editor visibility, omission of storage keys, student denial, and immediate denial after demotion. Student submission files remain in a separate table/API and are not part of this library.
- New CMS `parentId` and `missingTranslation` filters retain the same owner/role predicate and pagination. `missingTranslation=true` means only a blank Kazakh **title**, not proof that every translated body/block is complete. `catalogFiltersKeepPagingAndTeacherOwnership` verifies the totals, filtered items, summary-only response, and foreign-teacher exclusion.

## Assessment and legacy compatibility

Active assessment responses use `Assessment.publicView`, excluding answer keys; grading uses server-side frozen answers and the frozen question type. Context delivery now has its own public allowlist. Existing completed snapshots and stored scores are not rewritten. Legacy single-choice answers retain their one-point scoring, including Cyrillic option IDs, even though new authoring validation is stricter.

## Request limits and offline policy

`JsonRequestLimitFilter` bounds JSON bodies to 2 MiB before controller/Jackson processing, including vendor `+json` content types and requests without a declared Content-Length. Tests verify oversized known/unknown length rejection and that an accepted UTF-8 body remains readable downstream. Multipart limits and file validation remain separate; the JSON filter does not pretend to scan multipart bytes.

Offline export is an explicit public ENT THEORY allowlist. It rejects draft/archived/private-course content and omits editorial metadata. Attached bytes additionally require a published material, explicit offline rights, the public theory's permission, and `MaterialService.download` authorization/scan/integrity checks. The release owner's manifest change filters out optional `UNSCANNED` files when scanning is required, avoiding metadata that advertises a subsequently blocked download. No private course, student file, grade, token, or note is included by this backend export service. Offline revocation cannot erase a copy a user has already legitimately downloaded; the application must describe that limit accurately.
